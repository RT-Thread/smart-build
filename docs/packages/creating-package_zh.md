# 添加软件包

每个软件包使用一个小写、连字符命名的目录：

```text
packages/<name>/
  package.yaml
  Kconfig
  sbuild.py        # 用于 Python 构建后端
  patches/         # 可选
  conf/            # 可选
```

`package.yaml` 是软件包选择元数据的来源。`Kconfig` 由其生成，不得手动编辑。

## 选择构建后端

使用与软件包匹配的最简单后端：

- `build.objects` 根据明确的源码列表编译小型 C 库。
- `build.cmake` 构建仓库内的 CMake 可执行程序。
- `build.python.script` 运行仓库内受信任的 Python 构建代码，用于需要自定义
  适配的上游软件包。

自定义 `sbuild.py` 脚本属于受信任代码。它以构建用户权限执行，必须校验所需
输入，并且只能创建已声明的暂存输出。

## 添加归档源码元数据

使用不可变的发布归档和 SHA256 校验和：

```yaml
source:
  type: archive
  url: https://example.org/example-1.0.0.tar.xz
  archive: example-1.0.0.tar.xz
  sha256: <64 个小写十六进制字符>
  strip_root: true
  local_files:
    - sbuild.py
  files:
    - configure
    - src/main.c
```

`files` 和 `upstream_markers` 用于标识必需的上游内容。不要使用持续变化的分支
或没有加密校验和的归档。

## 编写 Python 构建脚本

Python 后端提供以下环境变量：

| 变量 | 含义 |
| --- | --- |
| `SMART_BUILD_PACKAGE` | 软件包名称 |
| `SMART_BUILD_SOURCE_DIR` | 准备好的上游源码目录 |
| `SMART_BUILD_WORK_DIR` | 软件包工作目录 |
| `SMART_BUILD_STAGE_DIR` | 软件包专用暂存目录 |
| `SMART_BUILD_STAGING_DIR` | 机器暂存根目录 |
| `SMART_BUILD_PACKAGES_STAGING_DIR` | 包含依赖软件包的暂存根目录 |
| `SMART_BUILD_TARGET` | 工具链目标三元组 |
| `SMART_BUILD_TOOLCHAIN_ROOT` | 解析后的工具链根目录 |
| `SMART_BUILD_TOOLCHAIN_BIN` | 解析后的工具链二进制目录 |
| `SMART_BUILD_CROSS_COMPILE` | 交叉编译器前缀 |
| `SMART_BUILD_INSTALL_PATH` | 可执行程序安装路径（如适用） |
| `SMART_BUILD_OUTPUT` | 旧版单一可执行程序工作输出（如适用） |

解析后的工具链还会提供 `CC`、`CXX`、`AR`、`RANLIB`、`STRIP` 和
`READELF` 等标准编译器变量。

所有安装文件都应使用 `build.python.outputs` 声明的 rootfs 路径，写入
`SMART_BUILD_STAGE_DIR` 下。暂存输出应创建普通文件而不是符号链接。命令或
校验失败时返回非零退出状态。

当前后端没有为 `--jobs` 或所选软件包选项提供稳定的环境变量。需要并行构建的
脚本目前自行选择任务数；添加软件包时应注意这一限制。

## 生成 Kconfig

仓库提供 `smart_build.package_kconfig` 生成函数，但当前 CLI 尚未公开生成
命令。从仓库根目录使用以下方式重新生成软件包文件和索引：

```sh
PYTHONPATH=src python - <<'PY'
from pathlib import Path

from smart_build.package_kconfig import (
    generate_package_kconfig_files,
    generate_package_kconfig_index,
)

root = Path.cwd()
for relative, content in generate_package_kconfig_files(root).items():
    (root / relative).write_text(content, encoding="utf-8")
(root / "packages/Kconfig").write_text(
    generate_package_kconfig_index(root), encoding="utf-8"
)
PY
```

构建前检查生成的差异。每个生成文件都以下列内容开头：

```text
# Generated by smart-build package metadata. Do not edit by hand.
```

## 验证软件包

至少运行：

```sh
./smart-build build package:<name>
python -m pytest
```

对于会加入 QEMU rootfs 的可执行程序，还应构建所选 rootfs 并运行
`./smart-build qemu-smoke`。确认暂存输出的架构正确，并在 RT-Thread Smart
中运行软件包的冒烟测试命令。
