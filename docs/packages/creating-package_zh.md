# 添加软件包

每个软件包使用一个小写、连字符命名的目录：

```text
packages/<name>/
  package.yaml
  Kconfig          # 生成式元数据后端
  sbuild.py        # 用于 Python 构建后端
  source/          # 独立 RT-Thread SCons 后端
    Kconfig
    SConstruct
    SConscript
    main.c
  patches/         # 可选
  conf/            # 可选
```

对于默认后端，`package.yaml` 是软件包选择元数据来源，`Kconfig` 由其生成。
独立 RT-Thread SCons 包则声明 `kconfig.mode: native`；其唯一 Kconfig 是
`source/Kconfig`，smart-build 不会重新生成它。

## 选择构建后端

使用与软件包匹配的最简单后端：

- `build.objects` 根据明确的源码列表编译小型 C 库。
- `build.cmake` 构建仓库内的 CMake 可执行程序。
- `build.python.script` 运行仓库内受信任的 Python 构建代码，用于需要自定义
  适配的上游软件包。
- `build.rtthread_scons` 通过固定的 `source/SConstruct` 入口和 `install` target
  构建经过调整的独立 RT-Thread 软件包。

自定义 `sbuild.py` 脚本属于受信任代码。它以构建用户权限执行，必须校验所需
输入，并且只能创建已声明的暂存输出。

RT-Thread SCons 文件同样属于受信任代码。此后端不是通用 SCons 适配层：应先把
软件包完整独立到 `source/` 下，移除相对 userapps 的路径和应用扫描，并使其
`install` target 遵守 `BUILD_DIR`、`DESTDIR`、`KCONFIG_CONFIG`、
`SMART_SDK_DIR`、`RTT_ROOT`、`RTTHREAD_TOOLS_DIR`、`CROSS_COMPILE` 和
`LINKAGE`。`SConstruct` 必须支持 `--pyconfig-silent`，加载本地 `SConscript`
及生成的 `packages/SConscript`，并使用传入的 RT-Thread 工具路径，不再采用
相对 userapps 的导入路径。完整契约见
[软件包描述文件参考](package-yaml_zh.md#独立-rt-thread-scons-后端)。

仓库中的 [`packages/webclient`](../../packages/webclient/README.md) 和
[`packages/webnet`](../../packages/webnet/README.md) 分别提供完整的客户端和
服务器示例；两者都会下载 RT-Thread 在线包，并通过 SCons 与本地 `main.c`
一起构建。

构建前可使用 `./smart-build configure package:<name>` 配置 native 包。
smart-build 只保存以 `kconfig.symbol` 为根的 Kconfig 配置子树；该步骤不会运行
SCons，也不会下载在线包。

native Kconfig 选择 RT-Thread 在线包时，smart-build 只在隔离 work 副本中执行
Env `pkgs --update`。不要把开发构建产生的 `.config`、`rtconfig.h`、
`pkg_config.h`、`.sconsign*`、`build/` 或 `packages/` 提交到 `source/`。

## 添加归档源码元数据

使用不可变的发布归档和 SHA256 校验和：

```yaml
source:
  type: archive
  url: https://example.org/example-1.0.0.tar.xz
  archive: example-1.0.0.tar.xz
  sha256: <64 个小写十六进制字符>
  strip_root: true
  local_files:
    - sbuild.py
  files:
    - configure
    - src/main.c
```

`files` 和 `upstream_markers` 用于标识必需的上游内容。不要使用持续变化的分支
或没有加密校验和的归档。

## 编写 Python 构建脚本

Python 后端提供以下环境变量：

| 变量 | 含义 |
| --- | --- |
| `SMART_BUILD_PACKAGE` | 软件包名称 |
| `SMART_BUILD_SOURCE_DIR` | 准备好的上游源码目录 |
| `SMART_BUILD_WORK_DIR` | 软件包工作目录 |
| `SMART_BUILD_STAGE_DIR` | 软件包专用暂存目录 |
| `SMART_BUILD_STAGING_DIR` | 机器暂存根目录 |
| `SMART_BUILD_PACKAGES_STAGING_DIR` | 包含依赖软件包的暂存根目录 |
| `SMART_BUILD_TARGET` | 工具链目标三元组 |
| `SMART_BUILD_TOOLCHAIN_ROOT` | 解析后的工具链根目录 |
| `SMART_BUILD_TOOLCHAIN_BIN` | 解析后的工具链二进制目录 |
| `SMART_BUILD_CROSS_COMPILE` | 交叉编译器前缀 |
| `SMART_BUILD_INSTALL_PATH` | 可执行程序安装路径（如适用） |
| `SMART_BUILD_OUTPUT` | 旧版单一可执行程序工作输出（如适用） |

解析后的工具链还会提供 `CC`、`CXX`、`AR`、`RANLIB`、`STRIP` 和
`READELF` 等标准编译器变量。

所有安装文件都应使用 `build.python.outputs` 声明的 rootfs 路径，写入
`SMART_BUILD_STAGE_DIR` 下。暂存输出应创建普通文件而不是符号链接。命令或
校验失败时返回非零退出状态。

当前后端没有为 `--jobs` 或所选软件包选项提供稳定的环境变量。需要并行构建的
脚本目前自行选择任务数；添加软件包时应注意这一限制。

## 生成 Kconfig

仓库提供 `smart_build.package_kconfig` 生成函数，但当前 CLI 尚未公开生成
命令。从仓库根目录使用以下方式重新生成软件包文件和索引：

```sh
PYTHONPATH=src python - <<'PY'
from pathlib import Path

from smart_build.package_kconfig import (
    generate_package_kconfig_files,
    generate_package_kconfig_index,
)

root = Path.cwd()
for relative, content in generate_package_kconfig_files(root).items():
    (root / relative).write_text(content, encoding="utf-8")
(root / "packages/Kconfig").write_text(
    generate_package_kconfig_index(root), encoding="utf-8"
)
PY
```

构建前检查生成的差异。每个生成文件都以下列内容开头：

```text
# Generated by smart-build package metadata. Do not edit by hand.
```

生成器会跳过 native 包的逐包 Kconfig 输出，并把其 `source/Kconfig` 直接加入
`packages/Kconfig`。

## 验证软件包

至少运行：

```sh
./smart-build build package:<name>
python -m pytest
```

对于会加入 QEMU rootfs 的可执行程序，还应构建所选 rootfs 并运行
`./smart-build qemu-smoke`。确认暂存输出的架构正确，并在 RT-Thread Smart
中运行软件包的冒烟测试命令。
