# Adding a package

Each package owns a lowercase, hyphenated directory:

```text
packages/<name>/
  package.yaml
  Kconfig
  sbuild.py        # for a Python build backend
  patches/         # optional
  conf/            # optional
```

`package.yaml` is the source for package selection metadata. `Kconfig` is
generated from it and must not be edited by hand.

## Choose a build backend

Use the simplest backend that matches the package:

- `build.objects` compiles a small C library from an explicit source list.
- `build.cmake` builds a repository-local CMake executable.
- `build.python.script` runs trusted repository-local Python build code for an
  upstream package requiring custom adaptation.

Custom `sbuild.py` scripts are trusted code. They execute with the build user's
permissions and must validate required inputs and create only declared staged
outputs.

## Add archive source metadata

Use an immutable release archive and SHA256 checksum:

```yaml
source:
  type: archive
  url: https://example.org/example-1.0.0.tar.xz
  archive: example-1.0.0.tar.xz
  sha256: <64 lowercase hexadecimal characters>
  strip_root: true
  local_files:
    - sbuild.py
  files:
    - configure
    - src/main.c
```

`files` and `upstream_markers` identify required upstream content. Do not use a
moving branch or an archive without a cryptographic checksum.

## Write a Python build script

The Python backend supplies these environment variables:

| Variable | Meaning |
| --- | --- |
| `SMART_BUILD_PACKAGE` | Package name |
| `SMART_BUILD_SOURCE_DIR` | Prepared upstream source directory |
| `SMART_BUILD_WORK_DIR` | Package work directory |
| `SMART_BUILD_STAGE_DIR` | Package-specific staging directory |
| `SMART_BUILD_STAGING_DIR` | Machine staging root |
| `SMART_BUILD_PACKAGES_STAGING_DIR` | Staging root containing dependency packages |
| `SMART_BUILD_TARGET` | Toolchain target triple |
| `SMART_BUILD_TOOLCHAIN_ROOT` | Resolved toolchain root |
| `SMART_BUILD_TOOLCHAIN_BIN` | Resolved toolchain binary directory |
| `SMART_BUILD_CROSS_COMPILE` | Cross-compiler prefix |
| `SMART_BUILD_INSTALL_PATH` | Executable install path, when applicable |
| `SMART_BUILD_OUTPUT` | Legacy single executable work output, when applicable |

Standard compiler variables such as `CC`, `CXX`, `AR`, `RANLIB`, `STRIP`, and
`READELF` are also supplied by the resolved toolchain.

Write all installed files below `SMART_BUILD_STAGE_DIR` using the rootfs paths
declared in `build.python.outputs`. Create regular files rather than symlinks
for staged outputs. Return a nonzero exit status when a command or validation
fails.

The current backend does not provide a stable environment variable for
`--jobs` or selected package options. Scripts requiring parallelism currently
choose their own job count; keep that limitation in mind when adding a package.

## Generate Kconfig

The repository provides `smart_build.package_kconfig` generation functions,
but the current CLI does not expose a generation command. From the repository
root, regenerate the package files and index with:

```sh
PYTHONPATH=src python - <<'PY'
from pathlib import Path

from smart_build.package_kconfig import (
    generate_package_kconfig_files,
    generate_package_kconfig_index,
)

root = Path.cwd()
for relative, content in generate_package_kconfig_files(root).items():
    (root / relative).write_text(content, encoding="utf-8")
(root / "packages/Kconfig").write_text(
    generate_package_kconfig_index(root), encoding="utf-8"
)
PY
```

Review the generated diff before building. Each generated file starts with:

```text
# Generated by smart-build package metadata. Do not edit by hand.
```

## Validate the package

At minimum:

```sh
./smart-build build package:<name>
python -m pytest
```

For an executable included in a QEMU rootfs, also build the selected rootfs and
run `./smart-build qemu-smoke`. Confirm the staged output architecture and the
package's smoke command inside RT-Thread Smart.
