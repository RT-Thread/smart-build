# 兼容性与当前限制

本页记录当前源码树中用户可见的限制。

## 安装方式

smart-build 目前需要从源码仓库运行。以可编辑模式安装 Python 软件包可以正常
工作，但独立 wheel 不包含也无法发现仓库中的板卡、软件包、根文件系统描述和
启动脚本布局。

## 构建规划

`build --dry-run` 和 `graph` 使用占位任务。完成工具链与软件包解析后，它们的
任务标识符、依赖和输出可能与真实构建不同。不要将这些输出当作稳定的自动化
API 使用。

## 并行任务

调度器串行执行任务。`--jobs` 会传递给 BusyBox，而部分软件包脚本自行根据
CPU 数量选择任务数。该选项目前不会对整个构建施加并发限制。

## 根文件系统镜像

目前仅实现 ext4 镜像创建。即使 Kconfig 界面显示 FAT 和 romfs，也无法构建
这些格式。

`ROOTFS=none` 与特定根文件系统目标命令的组合，并非在所有情况下都有一致的
QEMU 行为。

## 软件包选项

软件包选项值会被选择并记录，但通用后端和 Python 后端并不会始终使用这些
值。在软件包的构建实现能够证明选项会改变产物前，应将每个选项视为软件包
特定行为。

## 缓存和 manifest

缓存会校验输入签名以及输出是否存在，但命中时不会校验输出内容。发布或进行
可复现性检查前，应清理对应机器的构建目录。

构建 manifest 使用 `.yaml` 文件名，但内容为 JSON。当任务输入包含目录时，
它会记录宿主机绝对路径，并且文件可能较大。

## 源码版本

用户态软件包的发布归档通常使用 SHA256。BusyBox 目前使用 MD5，RT-Thread
源码自动检出则使用持续变化的分支。复现旧构建时，应保留本地源码版本。

RT-Thread 内核软件包版本来自板卡内核 defconfig 和已安装的 Env 软件包索引。
只有索引条目和上游归档仍然可用时，稳定版本才可复现。选择 `latest` 会跟随
软件包索引中变化的源码，并且每次更新都可能访问网络。

## QEMU 冒烟测试范围

冒烟测试只检测宽泛的启动标记，不能证明每个文件系统、网络服务、驱动程序或
打包应用均已成功初始化。发布测试应检查日志并运行目标特定的检查。
